### D-080 individual-therapy/private-note checkpoint

An explicit `individual_therapy` clinic service creates a dedicated visit type in the behavioral-health starter profile. An authorized clinician can keep routine treatment documentation in the existing ordinary encounter note and record private session analysis in a separate `clinic_psychotherapy_notes` table. The private note is encrypted, append-only and versioned with an exact request key, stale-version denial, reasoned revision and originator-only read. The clinician/site/patient authorization is checked on the server; the ordinary encounter note, chart history, portal and export contracts do not query the private table. The panel keeps unsaved text in memory and warns before navigation; it does not store private text in browser storage. Existing records are preserved when setup changes.

Source review 2026-09-22: [HHS psychotherapy-note guidance](https://www.hhs.gov/hipaa/for-professionals/faq/does-hipaa-provide-extra-protections-mental-health-information-compared-other-health.html), FAQ last reviewed 2017, defines separately maintained counseling-session analysis and distinguishes routine treatment information; it describes authorization for most disclosures to others. This informed separate storage, originator-only read and no automatic portal/export route, not a claim of legal conformance. Group therapy, mental-health professional eligibility, consent/authorization records, exceptional disclosure, retention, professional review and live use remain unresolved. The private note does not replace the ordinary progress note or close tasks. Final focused synthetic API proof passed 3 runs/39 assertions for save/retry/history, ciphertext, stale/role/visit denial and ordinary-chart isolation; frontend typecheck/build and scoped Ruby lint passed.
