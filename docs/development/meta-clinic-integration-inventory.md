# Meta Clinic integration inventory

The [Meta Clinic Implementation Tracker](../../APPlyVault/03%20Execution/Meta%20Clinic%20Implementation%20Tracker.md) owns delivery status and acceptance. This document is a source-oriented map for MC-15, not another task list or a claim that any vendor is connected. It applies D-067's narrow onboarding/integration role and D-072's direction to complete replaceable local workflows while vendor access is unavailable. See [Decisions: D-067](../../APPlyVault/03%20Execution/Decisions.md#d-067) and [Decisions: D-072](../../APPlyVault/03%20Execution/Decisions.md#build-local-workflows-before-vendor-access).

## Reading the status

- **Local workflow** means application code can prepare, record or reconcile the domain operation.
- **Simulator/manual** means local evidence is synthetic or entered by staff. It does not prove a vendor received, accepted or completed the operation.
- **Connected capability** means source contains a provider call/configuration path. It does not establish that credentials are present, the clinic is enabled, a live test passed or an external agreement exists.
- **External acceptance** requires separately recorded vendor/clinic evidence. No row below is marked externally accepted by this inventory.

## Cross-integration acceptance contract

For any future vendor adapter, continue from the existing domain owner and its persisted records. Do not introduce a generic framework or second ledger solely for hypothetical vendors. Before a live connector is scoped, identify the selected service and current official interface version, map source fields and response meanings, name unknowns, and agree how the clinic enables and disables that connection.

Local acceptance should use independently created synthetic data and cover success, rejection, unavailable service, timeout after possible acceptance, duplicate or out-of-order responses, stale prepared data, retry/idempotency, permission denial and tenant isolation. Prove that disconnected work remains visible and resumable, unknown outcomes require reconciliation, and obtaining credentials does not send old prepared work. Keep domain state separate from delivery attempts and distinguish manual, simulated and vendor-confirmed provenance.

Track three evidence levels independently in the tracker: local workflow behavior; backend simulator/contract and browser evidence; and live provider/clinic acceptance. Vendor selection, credentials, contracts, customer authorization, retention/privacy decisions, clinic operational ownership and cutover approval are human or external gates. A local test, sandbox configuration, successful redirect or saved status does not satisfy them.
