## Bounded implementation and standards mapping

Owned changes: `apps/web/src/features/patientPortal/IntakeQuestions.tsx`, `apps/web/test/intake-allergy-search.test.tsx`, and this dated record. The only product increment is a Material UI free-solo Autocomplete for an existing reported allergy substance name. It does not store a product ID, overwrite reaction type/details/another history entry, add a catalog, call a provider or change the API/schema. Catalog suggestions are not a comprehensive allergy terminology service.

Reviewed 2026-09-30: [US Core AllergyIntolerance 7.0.0 (R4)](https://hl7.org/fhir/us/core/STU7/StructureDefinition-us-core-allergyintolerance.html), applicable as U.S. allergy data-design guidance, and [Material UI 9.4 Autocomplete](https://mui.com/material-ui/react-autocomplete/), applicable to free-solo controls. No exchange partner/profile conformance is claimed. The existing local name/type/reaction/state contract is preserved; a catalog display name is not promoted into a coded allergen. MUI MCP was unavailable, so official documentation and installed 9.4 types were used. No new clinical fields, requiredness, prescribing rules or terminology mapping were selected.
