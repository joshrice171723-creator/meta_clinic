## Contracts and representation choices

- POST body: `{ "export": { "report_id": "daily_invoices", "filters": { "date": "2026-09-30", "page": 1 }, "request_key": "caller-generated-key" } }`. `201` for first issuance, `200` with `recovered: true` for the same saved request, `409` for conflicting key reuse. Source and filter values, dates, site ownership, active membership and action authorization are checked server-side.
- GET `/api/clinic/report_exports?report_id=...&date=...&page=...` returns up to 20 own-actor receipts and an older-page cursor. Optional `request_key` narrows recovery. GET `/:id` returns receipt and `source_snapshot`. GET `/:id/download` returns `{ export, artifact_csv }` through the existing session-aware JSON transport; the consumer creates the CSV file from verified UTF-8 bytes. Every endpoint uses `no-store`.
- Source digest input: recursively key-sorted JSON of `{ report_id, filters, serializer_revision, snapshot }`; arrays retain source query ordering and exact decimal strings. Artifact digest is SHA-256 of the stored UTF-8 CSV bytes. CSV carries request key, source digest, issuer/time, source definition, timezone/interval/as-of, input filters, and actual detail pagination. The separate receipt carries artifact digest to avoid a circular digest inside the artifact itself.
- The existing membership-generation lock stays in place. This controller supplies its outer repeatable-read transaction; the issuance service requires that isolation. Snapshot/unique conflicts discard any uncommitted rendered receipt and retry once. This is local transactional recovery, not external-call replay.
- Row/model history is protected against ordinary update/delete/truncate. Existing records require no backfill. Migration rollback is schema administration, not a user-visible correction or retention operation. Corrections are new explicit requests under new keys, preserving previous receipts.

Actor-only visibility, JSON transport for exact CSV bytes, serializer revision, capped pages/bytes, normalization, and strict creation exclusion for resettable lessons are conservative technical choices. Retention period, legal hold, named reconciliation/ownership policy, administrator-wide export audit visibility, broader export definitions, and clinical/PHI release applicability remain unresolved or outside this slice; they are not filled in with invented policy.
