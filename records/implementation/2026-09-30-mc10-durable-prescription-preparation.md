Date: 2026-09-30. Integration base: `10afe86357f94dc3c3d979647ccd809328005e8d` (`codex/mc10-attempt-provenance`). Authorized scope: source implementation and source-branch publication only. ## Implemented source contract

- `Clinic::Care::PrescriptionPreparation` is separate immutable, audited evidence: exact medication-request revision and manual review, preparation actor/time, stable request key, canonical SHA-256 envelope digest, pharmacy snapshot and existing simulation mode/signer/reviewer snapshots.
- `POST .../prepare` uses the existing patient/site/write authorization, active actor, idempotency receipt and prescription-series lock. It validates the same medication identity, explicit substitution, prescription details, outside-pharmacy destination and dependency requirements. It creates no prescription event or transmission attempt. It never changes the order's clinical or transmission status or adds sent/received evidence.
- `POST .../submit` now requires `preparation_id`. It rechecks current revision, destination snapshot/digest, mode/signer/reviewer context, unresolved outcomes and dependency readiness; each preparation can link to at most one immutable attempt. A destination row lock protects snapshot capture/recheck from concurrent directory edits.
- Saved prepare and submit requests retain their existing exact replay identity through `Clinic::Idempotency`. Exact submission replay returns its original attempt/correlation even after an unknown outcome; a different request is blocked pending original-attempt reconciliation. Replay does not repeat the submission operation.
- Evidence reads derive preparation state from linked attempt existence and expose source freshness separately. The MUI panel separates **Save prescription preparation** from **Submit to pharmacy (simulated)**, shows locally prepared/unsubmitted, source-changed and linked simulated outcome states, and labels historical attempts without preparation evidence. No external acknowledgment state is invented.
- Both synthetic sandbox submission callers explicitly prepare first. Existing API/service regression helpers were adapted for the required ID; a regression case was authored for no-send preparation, stable replay identity and changed-destination invalidation. All test execution is unrun.

## Legacy receipt replay correction — source-only follow-up

Supersedes the earlier compatibility limitation for an exact owned pre-migration retry. Inspection found that controller ID parsing and the added canonical preparation key rejected old requests before existing receipt replay. The submission controller now accepts an absent ID solely to reach the workflow receipt boundary. The workflow preserves the original canonical payload shape when the ID is absent, using the same operation, actor/practice/key lock, active membership and authorization callback, stored digest algorithm/key and exact digest comparison in `Clinic::Idempotency.execute`. A matched committed legacy receipt resolves only its existing practice-scoped attempt; it does not enter the submission block, infer preparation, change outcome or write any new evidence. Existing unknown attempt/correlation evidence remains unknown and subject to the original reconciliation block.

With no matched receipt, missing preparation is rejected immediately inside the new-write block, before series locking or preparation/event/attempt creation. A different payload/operation for an existing key still conflicts. A durable `outcome_unconfirmed` receipt raises the existing unresolved-outcome response even if it has a resource reference. No new receipt or automatic retry/send is introduced for this path. The new-attempt database trigger and preparation validation remain unchanged.

External clients must still prepare and supply `preparation_id` for every new submission. Old exact committed retries can now recover the original receipt-backed attempt without payload rewriting. Unknown/unconfirmed legacy evidence requires protected receipt lookup/reconciliation; this source correction does not resolve the outcome or create historical preparation. Static diff review only; tests/build/lint and runtime/migration checks remain unrun. Regression scenarios for later execution: committed old payload replay with unchanged identity/digest/counts; changed legacy payload conflict; wrong actor/tenant/permission denial; absent legacy receipt with no preparation rejected without writes; unconfirmed receipt remains unresolved; new prepared submission retains its ID-bound digest and replay behavior.
