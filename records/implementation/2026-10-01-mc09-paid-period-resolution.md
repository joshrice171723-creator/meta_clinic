## Authorized outcome

Staff with existing subscription billing payment authority can inspect competing paid-event evidence for an explicitly configured purchased service allowance, deliberately select one event, explain the selection and confirm it. The retained resolution determines future accounting for that exact competing set and half-open overlap interval. It is evidence selection, not a payment, default benefit policy, clinical decision, automatic winner, prorating or carryover rule.

The workflow enters through **Review paid-period overlaps** in the existing package-entitlement dialog. It shows exact event IDs, full UTC start/end boundaries, original event financial details and recorded times. Radio choices have no default. Reasons and a second confirmation are required. Read-only staff can inspect cases and history. The resolution history is paginated and preserves competing event snapshots, selected identity, reason, actor, effective time and request key.

## Conservative accounting and immutable history

- Resolution is per purchased service, complete competing paid-event set and exact interval. The interval ends at the next retained paid-event boundary; a changed/new event set requires new explicit evidence selection. No resolution is inherited into a different set.
- Only components with the existing fully configured retained allowance terms participate. Unconfigured agreements receive no configuration, selection, inferred balance or benefit grant.
- Future use records retain `period_resolution_id`; the exact action token includes that identity. Old entries retain NULL, original event/window/quantity and original request tokens. New entries also retain the server accounting time in nullable `accounted_at`, distinct from the ordinary creation timestamp, so the database guard checks the same business time as the service without backfilling old facts. No ledger rows are rewritten or moved.
- Usage for the same paid event/window is summed across old/new resolution identities, so selecting new evidence does not refill that window. Original reversals copy the original resolution identity and restore only that original window.
- A selection is blocked when another paid-event window has unreversed use overlapping the chosen allowance window. Accounting also blocks such competing usage after the original event overlap ends. Staff must inspect original evidence and, if appropriate, deliberately reverse exact original uses using the existing workflow; the resolver does not allocate or automatically reverse anything. It does not recommend reversal as a business or clinical decision.
- Selection/usage/reversal serialize on existing practice/patient/agreement locks. Exact resolution retry reauthorizes and returns only the same retained intent; changed reason/event/token on the same key conflicts. A stale competing set cannot silently select a new winner. Concurrent conflicting use is prevented by the additional insert guard.
